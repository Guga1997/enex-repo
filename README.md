# ონლაინ მაღაზია

E-commerce საიტი პროდუქტების ატვირთვით, ონლაინ გაყიდვებით, ფასეტური ფილტრით
და სტოკის API-ით გარე სისტემასთან დასაკავშირებლად.

**სტეკი:** Next.js 15 (App Router) · TypeScript · Prisma · SQLite · Tailwind CSS 4

---

## გაშვება

```bash
npm install
npm run db:push
npm run db:seed
npm run dev
```

საიტი: http://localhost:3000
ადმინი: http://localhost:3000/admin — `admin@example.ge` / `admin12345`

> **პირველი საქმე პროდაქშენამდე:** შეცვალე ადმინის პაროლი და `.env`-ში `AUTH_SECRET`.

## რა არის უკვე გაკეთებული

### კატალოგი და ფილტრი

- კატეგორიების ორდონიანი ხე (მთავარი → ქვეკატეგორია)
- **ფასეტური ფილტრი რაოდენობებით**, ყველა ფილტრი URL-ში (ბმული ზიარდება):
  - ფასის დიაპაზონი
  - ბრენდი
  - სტატუსი — მარაგშია / დროებით არ გვაქვს / გზაშია / წინასწარი შეკვეთით
  - ფასდაკლება, ახალი
  - **დინამიური მახასიათებლები** — რასაც პროდუქტს მიაწერ (რეზოლუცია, პორტები,
    სიმძლავრე), ავტომატურად ხდება ფილტრი
- რაოდენობები ერთმანეთს ითვალისწინებს: ბრენდის ფილტრი დარჩენილი ფილტრებით
  გამოთვლილ რიცხვებს აჩვენებს, საკუთარ თავს კი გამორიცხავს
- სორტირება, პაგინაცია, ძებნა დასახელებით/მოდელით/კოდით

### ნაშთის ლოგიკა

წარწერა ავტომატურად ითვლება რაოდენობიდან:

| მდგომარეობა | წარწერა |
|---|---|
| qty > lowStockAt | მარაგშია |
| qty ≤ lowStockAt | დარჩენილია N ცალი |
| qty ≤ 2 | დარჩენილია ბოლო ერთეულები |
| სტატუსი IN_TRANSIT | გზაშია, სავარაუდო ჩამოსვლა: DD.MM.YYYY |
| სტატუსი PREORDER | მხოლოდ წინასწარი შეკვეთით |
| qty = 0 | დროებით არ გვაქვს საწყობში |

### გაყიდვები

- კალათა (`localStorage`), checkout ფიზიკური და იურიდიული პირისთვის
- **ფასები და ნაშთი ყოველთვის სერვერზე მოწმდება** — კლიენტიდან მოსული ფასი იგნორირდება
- გადახდა: ბარათით (BOG), საბანკო გადარიცხვა, განვადება
- ნაშთი ჩამოიწერება მხოლოდ გადახდის დადასტურებაზე, იდემპოტენტურად
- შეკვეთის მოძებნა ნომრით + ელფოსტით

### ადმინ პანელი

პროდუქტების CRUD სურათების ატვირთვით, კატეგორიები, შეკვეთების მართვა,
სტოკის ცვლილებების ლოგი, API გასაღებების გაცემა.

## სტოკის API

ავთენტიფიკაცია: `Authorization: Bearer <გასაღები>` ან `X-API-Key: <გასაღები>`.
გასაღები იქმნება ადმინში → **API გასაღებები**. ინახება მხოლოდ ჰეშირებულად —
შექმნის შემდეგ ხელახლა ვერ ნახავ.

| მეთოდი | მისამართი | დანიშნულება |
|---|---|---|
| GET | `/api/v1/stock` | ყველა ნაშთი — `?page` `?limit` `?updated_since` |
| GET | `/api/v1/stock/{sku}` | ერთი პროდუქტის ნაშთი |
| PUT | `/api/v1/stock/{sku}` | ერთის განახლება |
| POST | `/api/v1/stock` | მასობრივი განახლება (2000 პოზიციამდე) |
| GET | `/api/v1/products` | კატალოგის ექსპორტი |
| POST | `/api/v1/products` | პროდუქტების შექმნა/განახლება SKU-ით |
| GET | `/api/v1/orders` | შეკვეთების წამოღება — `?status` `?since` |

### მაგალითი

```bash
curl -X POST http://localhost:3000/api/v1/stock \
  -H "Authorization: Bearer sk_live_..." \
  -H "Content-Type: application/json" \
  -d '{
    "items": [
      { "sku": "03904", "qty": 12, "price": 729.00 },
      { "sku": "03633", "qty": 0, "status": "IN_TRANSIT",
        "incomingDate": "2026-10-05T00:00:00.000Z" }
    ]
  }'
```

პასუხი:

```json
{ "updated": 2, "notFound": [], "skus": ["03904", "03633"] }
```

`qty`-ის გადმოცემისას სტატუსი თავად გამოითვლება (0 → არ გვაქვს, >0 → მარაგშია),
თუ `status` ცალკე არ მიუთითე. ყველა ცვლილება ჩაიწერება სტოკის ლოგში.

## BOG გადახდის ჩართვა

ახლა სისტემა **სატესტო რეჟიმშია** — `/payment/mock` ბანკის ნაცვლად.

1. აიღე merchant-ის `client_id` / `client_secret` საქართველოს ბანკიდან
2. `.env`-ში:
   ```
   BOG_CLIENT_ID="..."
   BOG_CLIENT_SECRET="..."
   BOG_PUBLIC_KEY="-----BEGIN PUBLIC KEY-----\n...\n-----END PUBLIC KEY-----"
   PAYMENT_MOCK=0
   NEXT_PUBLIC_SITE_URL="https://yourdomain.ge"
   ```
3. ბანკს მიაწოდე callback მისამართი: `https://yourdomain.ge/api/payments/bog/callback`

`BOG_PUBLIC_KEY` სავალდებულოა — მის გარეშე callback უარყოფილი იქნება, რაც ნიშნავს
რომ შეკვეთა გადახდილად არ მოინიშნება. ეს განზრახაა: ხელმოწერის შემოწმების გარეშე
ნებისმიერს შეეძლება ყალბი "გადახდილია" შეტყობინების გამოგზავნა.

თიბისის ეკვაირინგისთვის დაამატე `src/lib/payments/tbc.ts` იმავე ინტერფეისით
(`createPayment` / `verifyCallbackSignature`).

## პროდაქშენზე გატანამდე

სამი რამ სავალდებულოა:

1. **ბაზა** — `prisma/schema.prisma`-ში `provider = "postgresql"` და `DATABASE_URL`.
   SQLite ერთდროული ჩაწერისთვის არ ვარგა. შემდეგ `npx prisma migrate deploy`.
2. **სურათები** — ახლა `public/uploads`-ში ინახება, რაც Vercel-ზე ან რამდენიმე
   ინსტანსზე არ იმუშავებს. ჩაანაცვლე S3 / Cloudflare R2-ით — მხოლოდ
   `src/app/api/admin/upload/route.ts` შეიცვლება.
3. **`.env`** — `AUTH_SECRET` შემთხვევითი 32+ სიმბოლო, ადმინის პაროლი შეცვლილი.

სასურველი: შეკვეთის დადასტურების ელფოსტა (Resend/SendGrid), rate limiting
`/api/orders`-ზე, Sentry.
